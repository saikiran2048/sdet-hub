Q02
Explain your Automation Framework — all components

Walk through it layer by layer:

  • Build tool — Maven: dependency management, plugin execution, lifecycle phases
  • Driver management — WebDriverManager + DriverFactory using ThreadLocal<WebDriver> for parallel safety
  • Config management — ConfigReader reading .properties/YAML (URLs, timeouts, environment)
  • Page Object Model — one class per page, @FindBy locators, chainable methods
  • Test layer — TestNG / Cucumber step definitions calling page object methods
  • Data layer — Excel (Apache POI) or JSON (Jackson) via a DataProviderUtil
  • Reporting — Extent Reports / Allure with listeners for screenshots on failure
  • Logging — Log4j2
  • Retry mechanism — custom IRetryAnalyzer
  • API layer — REST Assured with Request/ResponseSpecification builders + POJOs
  • DB layer — JDBC + HikariCP connection pooling
  • CI/CD — Jenkins pipeline (checkout → build → test → publish reports → notify)
Close strong: "I built this incrementally — core Selenium+TestNG+Maven first, then layered in reporting, config, data-driven capability, retry logic, REST Assured, JDBC, and finally Jenkins CI/CD." Shows engineering maturity, not just tool-listing.

Q03
What is a Page Object Model?

A design pattern where each web page (or major component) is represented as a class containing:

  • Locators — as @FindBy-annotated WebElement fields
  • Methods — representing user actions (login(), clickSubmit())

Tests call these methods instead of touching locators directly, separating test logic from page structure. A locator change only needs updating in one place.

Q04
How do you run test cases in parallel in Cucumber?

A. TestNG-based runner with parallel data provider:

java@CucumberOptions(features = "src/test/resources/features", glue = "stepdefinitions")
public class TestRunner extends AbstractTestNGCucumberTests {
    @Override
    @DataProvider(parallel = true)
    public Object[][] scenarios() {
        return super.scenarios();
    }
}

And in testng.xml:

xml<suite name="Suite" parallel="methods" thread-count="4">

B. Cucumber-JVM Parallel Plugin — generates multiple runner classes at build time, each running a subset of features, executed in parallel via Surefire's forkCount/threadCount.

Critical: Either way, you need ThreadLocal<WebDriver> so each thread gets its own driver instance — otherwise threads collide on the same browser session.

Q06
What is a Singleton Design Pattern?

Ensures a class has only one instance for the entire JVM/application lifecycle, with a global access point.

javapublic class TokenManager {
    private static TokenManager instance;
    private String authToken;

    private TokenManager() {} // private constructor

    public static synchronized TokenManager getInstance() {
        if (instance == null) {
            instance = new TokenManager();
        }
        return instance;
    }

    public String getToken() { return authToken; }
    public void setToken(String token) { this.authToken = token; }
}

Common SDET use cases: TokenManager (avoid regenerating auth tokens per API call), ConfigManager, sometimes DriverFactory in non-parallel contexts.

Watch for follow-up: synchronized matters if multiple threads might initialize simultaneously — mention double-checked locking or an enum-based singleton as the thread-safe alternative.

Q08
What is Selenium Grid?

Lets you run tests on different machines, browsers, and OS combinations in parallel, distributed across nodes via a hub.

  • Hub — receives test requests and routes to nodes matching desired capabilities
  • Node — machine that actually runs the browser/test
  • Grid 4 architecture — Router, Distributor, Session Map, Node; supports Docker-based node registration

Purpose: reduce execution time and enable cross-browser/cross-platform coverage.

Q09
Explain the WebDriver create statement line
javaWebDriver driver = new ChromeDriver();
  • WebDriver — the interface (reference type) — gives browser-agnostic code
  • ChromeDriver — implementation class for Chrome (object type)
  • This is polymorphism — code to the interface so ChromeDriver swaps for FirefoxDriver/EdgeDriver without changing the rest of the code
  • Internally, ChromeDriver extends RemoteWebDriver, starts a chromedriver.exe process, and talks to the browser via the W3C WebDriver protocol (HTTP commands)
java// with WebDriverManager, run before the line above:
WebDriverManager.chromedriver().setup();

Q11
Explain the Maven Lifecycle

Three built-in lifecycles; the default lifecycle phases, in order:

validate → project structure is correct compile → compiles source code test → runs unit tests (Surefire plugin) package → packages compiled code (JAR/WAR) verify → runs integration checks install → installs package into local .m2 repo deploy → copies package to remote repo

Each phase runs all previous phases first. mvn install runs validate→compile→test→package→verify→install in sequence.

For automation runs you typically use mvn clean test — clean belongs to the separate clean lifecycle and wipes target/ first.

Q12
How do you run the failed test cases?

TestNG auto-generates test-output/testng-failed.xml after a run, listing only failed methods/classes:

bashmvn test -DsuiteXmlFile=test-output/testng-failed.xml

Cucumber — use the rerun plugin in @CucumberOptions:

javaplugin = {"rerun:target/rerun.txt"}

This writes failed scenario file:line references to rerun.txt; re-run with:

java@CucumberOptions(features = "@target/rerun.txt", ...)
Combine with IRetryAnalyzer to auto-retry flaky failures within the same run instead of needing a manual re-run pass.

Q15
What kind of waits are there in Selenium?
Wait typeBehavior
Implicit WaitGlobal wait applied to all findElement calls; polls DOM up to a fixed max time before NoSuchElementException
Explicit WaitWebDriverWait + ExpectedConditions; waits for a specific condition on a specific element
Fluent WaitLike explicit wait but configurable polling frequency and can ignore specific exceptions during the wait
Avoid mixing implicit and explicit waits in the same test — causes unpredictable wait behavior.

for (String window : allWindows) {

        driver.switchTo().window(window);
        break;
    }
}

driver.switchTo().window(parentWindow); // switch back

Q19
Why do we use Set in Window Handles?

getWindowHandles() returns a Set<String> because:

  • Each window handle is a unique identifier — Sets enforce uniqueness, preventing duplicate handles
  • Order of windows isn't guaranteed/relevant in most cases, so an unordered Set fits better than a List
  • Avoids the overhead/semantics of a List when uniqueness, not sequence, is the requirement

Q23
How do you decide the priorities of your Test Cases?
  • Business criticality — core flows (login, payment, checkout) first
  • Risk — areas with frequent defects or recent changes
  • Frequency of use — most-used features by end users
  • Regulatory/compliance impact — e.g. BFSI compliance flows must always be covered
  • Smoke vs regression — smoke = P0 (build verification), regression = P1/P2 by module criticality

Often tagged: @P0/@critical, @P1, @P2 — prioritized in CI pipelines (P0 on every commit, full regression nightly).

Q26

@BeforeSuite @BeforeTest @BeforeClass @BeforeMethod @Test @AfterMethod @AfterClass @AfterTest @AfterSuite

@BeforeMethod/@AfterMethod runs around every @Test; @BeforeClass/@AfterClass once per class; @BeforeTest/@AfterTest once per <test> tag in testng.xml; @BeforeSuite/@AfterSuite once for the whole suite run.

Q27
What is the defect life cycle?
New → Assigned → Open (In Progress) → Fixed → Pending Retest → Retest → Verified → Closed ↓ Reopened (if retest fails) → back to Assigned

Other states: Deferred (postponed to a later release), Rejected (not a valid defect), Duplicate.

As an SDET, log defects with: steps to reproduce, expected vs actual result, environment, severity, priority, and attach logs/screenshots — often integrated directly with Jira/Azure DevOps from automation failure reports.

Q30
Difference between 401 and 403 Status Code
CodeMeaning
401 UnauthorizedAuthentication failure — client isn't authenticated at all, or credentials/token are missing/invalid. Server doesn't know who you are.
403 ForbiddenAuthorization failure — client IS authenticated but doesn't have permission to access this resource.
Quick recall: 401 = "who are you?"  |  403 = "I know who you are, but no."

Q31
What are the components of an API Request?
  • Endpoint/URL — the resource address
  • HTTP Method — GET, POST, PUT, PATCH, DELETE
  • Headers — metadata (Content-Type, Authorization, Accept)
  • Path Parameters — part of the URL identifying a specific resource (/users/{id})
  • Query Parameters — key-value pairs for filtering/sorting (?status=active&page=2)
  • Request Body/Payload — data sent (JSON/XML), mainly for POST/PUT/PATCH
  • Authentication — token, API key, basic auth credentials

Q33
How do you resolve Conflicts in Git?

git pull (or merge) triggers a conflict — Git marks conflicting sections in the file:

text<<<<<<< HEAD
your changes
=======
incoming changes
>>>>>>> branch-name

Resolution steps:

  1. Open the file, manually decide which changes to keep (or combine both), remove the conflict markers
  2. git add <file> to mark as resolved
  3. git commit to complete the merge (or git rebase --continue if rebasing)
  4. git push
Tools like VS Code's merge editor or git mergetool simplify this visually. Best practice: pull frequently, keep commits small, communicate with the team to avoid conflicts in the first place.

Q34
Difference between git pull and git patch
Note: there's no command literally called git patch — likely meant git format-patch / git apply. It's fine to politely clarify this in an interview.
CommandWhat it does
git pullgit fetch + git merge — fetches commits from a remote branch and merges them into your current branch directly. Requires network access to the remote.
git format-patch / git applyGenerates .patch files representing commits as diffs (can be emailed/transferred manually), then applied elsewhere via git apply or git am — useful without direct repo connectivity between two systems.
bash# generate patch files for last 3 commits
git format-patch -3

# apply a patch file
git apply 0001-fix-login-bug.patch

Q35
Explain the use of Jenkins in the Automation Framework
  • CI/CD orchestration — triggers automated test runs on commits, scheduled intervals, or manual triggers
  • Pipeline as code — Jenkinsfile defines stages: checkout → build → test → publish reports → notify
  • Parameterized builds — pass environment, browser, tag filters at trigger time
  • VCS integration — webhooks from GitHub/Azure Repos auto-trigger builds on push/PR
  • Report publishing — HTML Publisher, Allure, Cucumber Reports plugins show results in the build dashboard
  • Notifications — email/Slack/Teams on build pass/fail
  • Scheduling — cron-style triggers for nightly/weekly regression
  • Distributed builds — integrates with Selenium Grid/Docker agents for parallel cross-browser execution
groovypipeline {
    agent any
    stages {
        stage('Checkout') {
            steps { git 'https://github.com/org/repo.git' }
        }
        stage('Build') {
            steps { sh 'mvn clean compile' }
        }
        stage('Test') {
            steps { sh 'mvn test -Dcucumber.filter.tags="@smoke"' }
        }
        stage('Publish Report') {
            steps { publishHTML(target: [reportDir: 'target', reportFiles: 'cucumber-reports.html']) }
        }
    }
}

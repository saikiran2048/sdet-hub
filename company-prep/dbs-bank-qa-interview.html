✓ R1.01 Validate whether text is highlighted and underlined on a webpage ▸

Selenium has no built-in "is highlighted" or "is underlined" check — these are CSS rendering effects, so you read the computed CSS via getCssValue(). Think of it like checking a document with a magnifying glass: Selenium can't "see" the highlighter pen, but it can read the paint underneath.

WebElement element = driver.findElement(By.id("targetText"));

// Underline check
String textDecoration = element.getCssValue("text-decoration-line");
boolean isUnderlined = textDecoration.contains("underline");

// Highlight check (commonly background-color)
String backgroundColor = element.getCssValue("background-color");
boolean isHighlighted = !backgroundColor.equalsIgnoreCase("rgba(0, 0, 0, 0)")
        && !backgroundColor.equalsIgnoreCase("transparent");

System.out.println("Underlined: " + isUnderlined);
System.out.println("Highlighted: " + isHighlighted);

Assert.assertTrue(isUnderlined, "Text is not underlined");
Assert.assertTrue(isHighlighted, "Text is not highlighted");

Note: If the highlight is applied via a <mark> tag or a specific class instead of inline background-color, it's more robust to assert on the tag name or CSS class rather than a raw color value.

✓ R1.02 Purpose of the `Background` section in Cucumber ▸

Background is like a "before each scene" setup in a play — every actor needs to be in position before the scene (Scenario) starts. It holds Given steps that are common to every Scenario in a Feature file, so you don't repeat the same setup steps over and over.

Feature: Fund Transfer

  Background:
    Given the user is logged into the banking portal
    And the user is on the "Fund Transfer" page

  Scenario: Successful transfer within own accounts
    When the user transfers 5000 to account "12345"
    Then the transaction should be successful

  Scenario: Transfer fails when balance is insufficient
    When the user transfers 999999 to account "12345"
    Then the transaction should be declined

It runs before every Scenario in that Feature (similar to @BeforeMethod in TestNG), keeping feature files DRY and readable.

✓ R1.03 Difference between `And` and `But` in Cucumber ▸

Functionally, there is no difference — Cucumber treats both as a continuation of the preceding Given/When/Then keyword. They exist purely for readability:

Keyword Typical usage Analogy
And Adds another step of the same polarity (positive condition) "...and also do this"
But Adds a step that expresses a contrast or negative condition "...but not this" 
Scenario: Login validation
  Given the user is on the login page
  And the user enters valid credentials
  When the user clicks login
  Then the dashboard should be displayed
  But an error message should not appear

Both And and But are converted internally by the step-matching engine to whatever the previous concrete keyword was (Given/When/Then) — it's purely syntactic sugar for the human reader.

✓ R1.04 What is a Scenario Outline in Cucumber? ▸

A Scenario Outline is a template scenario run multiple times with different sets of data — think of it as a for loop or a TestNG @DataProvider for Gherkin. Each row in the Examples table becomes one full test execution.

Scenario Outline: Login with different credential sets
  Given the user is on the login page
  When the user enters username "<username>" and password "<password>"
  Then the login result should be "<result>"

  Examples:
    | username   | password   | result  |
    | dbsuser1   | Pass@123   | success |
    | dbsuser2   | wrongpass  | failure |
    | invalidUsr | Pass@123   | failure |

Use it whenever the steps stay the same but the input/output data varies — avoids copy-pasting near-identical scenarios.

public class SpaceReducer {
    public static String normalizeSpaces(String input) {
        if (input == null) return null;
        return input.trim().replaceAll("\\s+", " ");
    }

    public static void main(String[] args) {
        String input = "I  am   Testing";

✓ R1.11 Can we execute a Java program without a `main()` method? ▸

In modern Java (JDK 7+), no — this is a common trick question. There used to be a workaround using a static initializer block, since static blocks run during class loading, before main() is invoked:

public class NoMain {
    static {
        System.out.println("Static block executed");
        System.exit(0); // needed pre-JDK7 to avoid "main not found" error after the block ran
    }
}
  • Pre-JDK 6: This worked — the static block ran, then the JVM threw a NoSuchMethodError for main, but System.exit(0) stopped execution before that error surfaced.
  • JDK 7 onward: The JVM now checks for the presence of a valid main() method before initializing the class at all, so the static block never even runs. You'll get a direct error: Error: Main method not found in class NoMain.

So the honest answer: not with a standard java launch on any current JDK.

✓ R1.12 What happens if `main()` is declared `private`? ▸

The code compiles successfully — the compiler doesn't enforce access modifiers on main. But at runtime, the JVM's launcher specifically looks for a public static void main(String[] args). Since a private method isn't visible to the JVM launcher, you get:

Error: Main method not found in class HelloWorld, please define the main method as:
   public static void main(String[] args)

public class HelloWorld {
    private static void main(String[] args) { // compiles fine
        System.out.println("Hello");
    }
}
// Runtime error: Main method not found
✓ R1.13 How to check whether an array is empty or `null` in Java ▸ 
public static boolean isEmptyOrNull(int[] array) {
    return array == null || array.length == 0;
}

Always check null first with && short-circuit ordering — if you check array.length == 0 before array == null, you'd get a NullPointerException on a null array.

int[] arr1 = null;
int[] arr2 = new int[0];
int[] arr3 = {1, 2, 3};

System.out.println(isEmptyOrNull(arr1)); // true
System.out.println(isEmptyOrNull(arr2)); // true
System.out.println(isEmptyOrNull(arr3)); // false
✓ R1.14 SQL queries using `WHERE`, `ORDER BY`, and `GROUP BY` ▸

Assume a table transactions(txn_id, account_id, amount, txn_date, status).

-- WHERE: filter rows
SELECT txn_id, account_id, amount, status
FROM transactions
WHERE status = 'FAILED';

-- ORDER BY: sort results (descending by amount)
SELECT txn_id, account_id, amount
FROM transactions
WHERE status = 'SUCCESS'
ORDER BY amount DESC;

-- GROUP BY: aggregate rows (count of transactions per account)
SELECT account_id, COUNT(*) AS total_transactions, SUM(amount) AS total_amount
FROM transactions
GROUP BY account_id;

-- Combined: WHERE + GROUP BY + HAVING + ORDER BY
SELECT account_id, COUNT(*) AS failed_count
FROM transactions
WHERE status = 'FAILED'
GROUP BY account_id
HAVING COUNT(*) > 3
ORDER BY failed_count DESC;

Execution order to remember: WHERE filters rows before grouping; HAVING filters after grouping; ORDER BY runs last.

✓ R1.15 Explain Jenkins and its role in automation testing ▸

Jenkins is an open-source CI/CD automation server — think of it as the factory assembly-line manager: every time a developer commits code, Jenkins automatically picks it up, builds it, runs the tests, and reports back — without a human needing to trigger each step manually.

Role in automation testing: - Triggers test execution automatically — on every code commit (via webhook), on a schedule (cron), or on-demand. - Runs your TestNG/Cucumber suites as part of a build Pipeline (Jenkinsfile), often via Maven/Gradle commands (mvn test). - Publishes reports — integrates with plugins (e.g., Cucumber Reports, TestNG Results, Allure) to visualize pass/fail trends over builds. - Enables CI/CD — ties automated regression suites into the deployment pipeline, so code isn't promoted to the next environment unless tests pass (a "quality gate"). - Parallel & distributed execution — can distribute test runs across multiple agent nodes to cut execution time.

// Simplified Jenkinsfile example
pipeline {
    agent any
    stages {
        stage('Checkout') {
            steps { git 'https://github.com/company/automation-suite.git' }
        }
        stage('Run Tests') {
            steps { sh 'mvn clean test -Dsurefire.suiteXmlFiles=testng.xml' }
        }
        stage('Publish Report') {
            steps { cucumber buildStatus: 'UNSTABLE', jsonReportDirectory: 'target/cucumber-reports' }
        }
    }
}

In short: Jenkins is the glue that turns your Selenium/Cucumber/TestNG suite from "something I run manually on my laptop" into "something that runs automatically, consistently, and reports results on every change."

✓ R2.01 Difference between Implicit Wait, Explicit Wait, and Fluent Wait in Selenium ▸

Think of it like waiting for a bus: Implicit wait is a blanket rule — "I'll wait up to 10 seconds at every stop, no matter what." Explicit wait is specific — "I'll wait up to 10 seconds, but only at this stop, for this bus to arrive." Fluent wait is the most flexible — "I'll wait up to 10 seconds, checking every 2 seconds, and I'll ignore it if a stray dog runs past (ignoring certain exceptions)."

// Implicit wait — applies globally to all findElement calls
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));

// Explicit wait — condition-specific, for one element
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
WebElement el = wait.until(ExpectedConditions.elementToBeClickable(By.id("submitBtn")));

// Fluent wait — custom polling interval + exceptions to ignore
Wait<WebDriver> fluentWait = new FluentWait<>(driver)
        .withTimeout(Duration.ofSeconds(20))
        .pollingEvery(Duration.ofSeconds(2))
        .ignoring(NoSuchElementException.class);

WebElement el2 = fluentWait.until(d -> d.findElement(By.id("submitBtn")));

Rule of thumb: never mix implicit and explicit waits in the same script — it causes unpredictable wait times.

✓ R2.02 How do you handle a dropdown in Selenium WebDriver? ▸

WebElement dropdownElement = driver.findElement(By.id("country"));

✓ R2.03 How do you switch between multiple windows/tabs in Selenium? ▸

Every browser window/tab has a unique handle (like a ticket number). You capture the current handle, get the set of all handles, and switch to the one you need.

String parentWindow = driver.getWindowHandle();

// Trigger action that opens a new tab/window
driver.findElement(By.id("openNewTabLink")).click();

Set<String> allWindows = driver.getWindowHandles();
for (String handle : allWindows) {
    if (!handle.equals(parentWindow)) {
        driver.switchTo().window(handle);
        break;
    }
}

// Do actions in the new window...
driver.close(); // close current (child) window
driver.switchTo().window(parentWindow); // go back to parent
✓ R2.04 How do you handle an iframe in Selenium? ▸

An iframe is like a "window within a window" — Selenium's default focus is the main page, so you must explicitly step into the iframe before interacting with elements inside it, and step back out afterward.

✓ R2.05 How do you handle a JavaScript alert/popup in Selenium? ▸

Selenium interacts with native JS alerts through the Alert interface — you can't click them with normal findElement calls since they're outside the DOM.

✓ R2.06 What is `StaleElementReferenceException` and how do you handle it? ▸

This happens when the DOM has changed after you located an element — the reference you're holding points to an element that's no longer attached to the page (e.g., after a page reload, an AJAX re-render, or a navigation). It's like holding a claim ticket for a coat that the cloakroom just reorganized — the ticket number no longer matches anything.

Handling strategies:

// Re-locate the element right before interacting with it, instead of caching it early
public void safeClick(By locator) {
    int attempts = 0;
    while (attempts < 3) {
        try {
            driver.findElement(locator).click();
            break;
        } catch (StaleElementReferenceException e) {
            attempts++;
        }
    }
}

Other fixes: use explicit waits with ExpectedConditions.refreshed(...), avoid storing WebElement references across page transitions, and re-fetch elements inside loops rather than outside them.

✓ R2.07 What are Cucumber Hooks? Explain `@Before` and `@After` ▸

Hooks are setup/teardown blocks that run around every Scenario, similar to @BeforeMethod/@AfterMethod in TestNG — but they live in a dedicated "hooks" class rather than the feature file.

public class Hooks {

    @Before
    public void setUp(Scenario scenario) {
        driver = new ChromeDriver();
        System.out.println("Starting scenario: " + scenario.getName());
    }

    @After
    public void tearDown(Scenario scenario) {
        if (scenario.isFailed()) {
            byte[] screenshot = ((TakesScreenshot) driver).getScreenshotAs(OutputType.BYTES);
            scenario.attach(screenshot, "image/png", "FailureScreenshot");
        }
        driver.quit();
    }
}
  • @Before runs before each Scenario (e.g., launch browser, log in).
  • @After runs after each Scenario (e.g., attach screenshots on failure, quit driver).
  • You can also scope hooks with tags: @Before("@regression") runs only before scenarios tagged @regression.
✓ R2.08 How do you pass a Data Table in Cucumber and read it in step definitions? ▸

public void submitCustomerDetails(DataTable dataTable) {

✓ R2.10 Difference between `@BeforeMethod`, `@BeforeClass`, `@BeforeSuite` in TestNG ▸

They differ purely by scope/frequency — like the difference between prepping before every customer, prepping once per store, and prepping once for the entire company:

Annotation Runs Typical use
@BeforeMethod Before every @Test method Navigate to a fresh page, reset test data
@BeforeClass Once, before the first test method in that class Initialize WebDriver for the class
@BeforeSuite Once, before all tests in the entire suite (across classes) Read global config, start reporting, set up environment 
@BeforeSuite

public void classSetup() { driver = new ChromeDriver(); }

✓ R2.11 How do you set test priority and dependency in TestNG? ▸

Priority controls the order tests run in (lower number runs first); dependency enforces that a test only runs if another test passed.

public class LoginTests {

    @Test(priority = 1)
    public void testValidLogin() {
        // runs first
    }

    @Test(priority = 2, dependsOnMethods = "testValidLogin")
    public void testDashboardLoads() {
        // only runs if testValidLogin passed; runs after it
    }
}

If testValidLogin fails, testDashboardLoads is automatically skipped (not failed) — TestNG assumes it's pointless to check the dashboard if login itself didn't work.

✓ R2.12 Difference between hard assert and soft assert in TestNG ▸

A hard assert (Assert) is like a security guard who stops you the instant you break one rule — the test halts immediately on the first failure. A soft assert (SoftAssert) is like an inspector who notes down every violation on a checklist, then reports all of them at the end.

// Hard assert — stops execution immediately on failure
Assert.assertEquals(actualTitle, expectedTitle);
Assert.assertTrue(isLoginSuccessful); // never reached if above fails

// Soft assert — collects failures, continues execution
SoftAssert softAssert = new SoftAssert();
softAssert.assertEquals(actualTitle, expectedTitle);
softAssert.assertTrue(isLoginSuccessful);
softAssert.assertAll(); // must call this at the end to actually report failures

Use soft asserts when validating multiple independent fields on one page (e.g., checking 5 labels), so you get a full picture of what's broken in one run instead of fixing failures one at a time.

✓ R2.13 Difference between an abstract class and an interface in Java ▸

Both allow abstraction, but they answer different questions: an abstract class answers "what is this thing" (an "is-a" relationship with shared state), while an interface answers "what can this thing do" (a contract of capabilities).

Constructor Can have a constructor Cannot have a constructor
Use case Shared base behavior across closely related classes Defining a capability/contract across unrelated classes

    String brand;

✓ R2.14 Difference between checked and unchecked exceptions in Java ▸

✓ R2.17 Difference between `git merge` and `git rebase` ▸

Both integrate changes from one branch into another, but they tell the story differently — merge is like stapling two documents together with a note ("these were combined here"), keeping full history intact with a merge commit. rebase is like retyping your document's pages on top of the latest version, producing a clean, linear history with no merge commit.

Aspect git merge git rebase
History Preserves full branching history (creates a merge commit) Rewrites history — replays your commits on top of the target branch
Commit graph Non-linear (shows branches/merges) Linear (looks like work happened sequentially)
Safety on shared branches Safe — doesn't rewrite existing commits Risky on shared/public branches — rewrites commit hashes
Typical use Merging a completed feature branch into main Keeping a local feature branch up to date with main before raising a PR 
# merge
git checkout main
git merge feature-branch

# rebase
git checkout feature-branch
git rebase main

Golden rule: never rebase a branch that others have already pulled/pushed to — it rewrites commit history and breaks their local copies.

✓ R2.18 What is `git cherry-pick` and when would you use it? ▸

cherry-pick lets you take one specific commit from another branch and apply it onto your current branch — without merging the whole branch. It's like picking a single ripe fruit from a neighboring tree instead of chopping down the whole branch.

git checkout main
git cherry-pick a1b2c3d   # applies just that one commit's changes onto main

Common use case in QA automation: a critical bug-fix commit was made on a feature branch, but you don't want the rest of that branch's unfinished work — you cherry-pick just the fix commit onto main or a hotfix branch.

✓ R2.19 Difference between `INNER JOIN` and `LEFT JOIN` in SQL ▸

INNER JOIN returns only the rows that match in both tables — like the overlapping section of a Venn diagram. LEFT JOIN returns all rows from the left table, plus matching rows from the right table (or NULL if there's no match) — like keeping the entire left circle and only borrowing overlap from the right.

-- INNER JOIN: only accounts that have at least one transaction
SELECT a.account_id, t.txn_id, t.amount
FROM accounts a
INNER JOIN transactions t ON a.account_id = t.account_id;

-- LEFT JOIN: all accounts, even those with zero transactions (txn columns will be NULL)
SELECT a.account_id, t.txn_id, t.amount
FROM accounts a

✓ R3.01 What is REST Assured, and how do you validate a GET API's status code and JSON body? ▸

REST Assured is a Java library that lets you write API tests in a fluent, readable style — like writing a sentence: "Given these headers, When I call this endpoint, Then I expect this response." It removes the boilerplate of manually building HTTP requests with raw HttpURLConnection.

✓ R3.02 Difference between GET, POST, PUT, PATCH, DELETE HTTP methods ▸

Think of a customer record like a form: GET reads it, POST creates a brand-new one, PUT replaces the entire form with a new version, PATCH edits just one field on the existing form, and DELETE throws the form away.

Method Purpose Idempotent? Typical body
GET Retrieve a resource Yes None
POST Create a new resource No Yes — full resource data
PUT Replace an entire existing resource Yes Yes — full resource data
PATCH Partially update a resource No (usually) Yes — only changed fields
DELETE Remove a resource Yes Usually none

Idempotent means calling it multiple times has the same effect as calling it once — e.g., deleting an already-deleted record still results in "record gone," but posting the same data twice creates two records.

public static String reverseString(String input) {
    char[] chars = input.toCharArray();
    int left = 0, right = chars.length - 1;
    while (left < right) {
        char temp = chars[left];
        chars[left] = chars[right];
        chars[right] = temp;
        left++;
        right--;
    }
    return new String(chars);
}
// reverseString("Testing") -> "gnitseT"

        left++;
        right--;
    }
    return true;
}

✓ R3.10 Find duplicate elements in an array ▸ 
public static Set<Integer> findDuplicates(int[] arr) {
    Set<Integer> seen = new HashSet<>();
    Set<Integer> duplicates = new LinkedHashSet<>();
    for (int num : arr) {
        if (!seen.add(num)) {
            duplicates.add(num);
        }
    }
    return duplicates;
}
// findDuplicates({1,2,3,2,4,1,5}) -> [2, 1]

seen.add(num) returns false if the element already exists in the set — that's the signal it's a duplicate.

✓ R3.11 Find the second largest element in an array ▸ 
public static int secondLargest(int[] arr) {
    int largest = Integer.MIN_VALUE, secondLargest = Integer.MIN_VALUE;
    for (int num : arr) {
        if (num > largest) {
            secondLargest = largest;
            largest = num;
        } else if (num > secondLargest && num != largest) {
            secondLargest = num;
        }
    }
    return secondLargest;
}
// secondLargest({10, 25, 3, 25, 18}) -> 18

Single pass, O(n) — no need to sort the entire array just to find two values.

public static boolean isAnagram(String s1, String s2) {
    char[] a = s1.toLowerCase().replaceAll("\\s", "").toCharArray();
    char[] b = s2.toLowerCase().replaceAll("\\s", "").toCharArray();
    if (a.length != b.length) return false;
    Arrays.sort(a);
    Arrays.sort(b);
    return Arrays.equals(a, b);
}
// isAnagram("listen", "silent") -> true

✓ R3.14 Find the first non-repeated character in a string ▸ 
public static Character firstNonRepeatedChar(String input) {
    Map<Character, Integer> freq = new LinkedHashMap<>();
    for (char c : input.toCharArray()) {
        freq.put(c, freq.getOrDefault(c, 0) + 1);
    }
    for (Map.Entry<Character, Integer> entry : freq.entrySet()) {
        if (entry.getValue() == 1) return entry.getKey();
    }
    return null; // no non-repeated character found
}

✓ R4.01 What are XPath axes? Give examples for dynamic elements ▸

XPath axes let you navigate the DOM relative to a known element — like giving directions relative to a landmark ("two doors down from the bakery") instead of a fixed address, which is essential when an element itself has no unique ID but a nearby element does.

// parent::  — go up to the immediate parent
driver.findElement(By.xpath("//input[@id='email']/parent::div"));

// following-sibling:: — next sibling element(s)
driver.findElement(By.xpath("//label[text()='Email']/following-sibling::input"));

// preceding-sibling:: — previous sibling element(s)
driver.findElement(By.xpath("//input[@id='submitBtn']/preceding-sibling::input"));

// ancestor:: — any ancestor up the tree
driver.findElement(By.xpath("//span[text()='Error']/ancestor::form"));

// descendant:: — any descendant down the tree
driver.findElement(By.xpath("//div[@id='card']/descendant::button"));

// contains() and text() — for dynamic/partial attribute matching
driver.findElement(By.xpath("//button[contains(@class,'btn-primary')]"));
driver.findElement(By.xpath("//*[text()='Submit']"));

These axes are the go-to fix when a target element has no reliable locator of its own but sits near one that does (a very common situation in poorly-tagged banking UI grids/tables).

✓ R4.02 CSS Selector vs XPath — which is faster and why? ▸

Both locate elements, but CSS Selectors are generally faster because browsers have a native, highly optimized CSS engine (used for styling every page anyway), whereas XPath relies on a separate, more general-purpose traversal engine — like taking a dedicated highway (CSS) versus a scenic backroad that can go anywhere but isn't built for speed (XPath).

Aspect CSS Selector XPath
Speed Faster (native browser engine) Slower (especially in older IE, less so in modern browsers)
Traverse upward (parent) Not possible Possible (parent::, ancestor::)
Text-based matching Not supported directly Supported (text(), contains())
Readability Generally shorter/cleaner Can get verbose
Cross-browser support Excellent Excellent 
// CSS
driver.findElement(By.cssSelector("input#email"));
driver.findElement(By.cssSelector("div.card > button.primary"));

// XPath (needed here because CSS can't go "upward" or match by text)
driver.findElement(By.xpath("//button[text()='Submit']/ancestor::form"));

Practical guidance: prefer CSS for straightforward locators; fall back to XPath only when you need text matching or upward traversal.

✓ R4.04 How do you run tests in parallel using TestNG, and how do you avoid WebDriver conflicts? ▸

TestNG supports parallel execution at the methods, classes, tests, or suites level via testng.xml. The danger is that if all threads share one static WebDriver instance, they'll interfere with each other — like multiple people trying to drive the same car at once. The fix is ThreadLocal<WebDriver>, giving each thread its own isolated driver instance.

<suite name="RegressionSuite" parallel="methods" thread-count="4">
    <test name="LoginTests">
        <classes>
            <class name="tests.LoginTest"/>
        </classes>
    </test>
</suite>

public class DriverManager {
    private static ThreadLocal<WebDriver> driver = new ThreadLocal<>();

    public static void setDriver() {
        driver.set(new ChromeDriver());
    }

    public static WebDriver getDriver() {
        return driver.get();
    }

    public static void quitDriver() {
        driver.get().quit();
        driver.remove();
    }
}

Each thread calls getDriver() and gets its own browser instance — no shared state, no race conditions.

✓ R4.09 Difference between `==` and `.equals()`, and why override `equals()` and `hashCode()` together ▸

== compares references (are these two variables pointing to the exact same object in memory?), while .equals() compares content/value (do these two objects logically represent the same thing?) — like comparing whether two people are holding the same physical photograph (==) versus whether the photographs look identical (.equals()).

String a = new String("DBS");
String b = new String("DBS");

System.out.println(a == b);        // false — different objects in memory
System.out.println(a.equals(b));   // true — same content

Why override both together: Java's contract states that if two objects are .equals(), they must produce the same hashCode() — otherwise, collections like HashMap/HashSet break (an object could be "equal" to another but stored in a different bucket, so lookups silently fail).

@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Account)) return false;
    Account acc = (Account) o;
    return this.accountId.equals(acc.accountId);
}

@Override
public int hashCode() {
    return Objects.hash(accountId);
}
✓ R4.10 Difference between `Comparable` and `Comparator` in Java ▸

Comparable defines an object's natural, default sort order — built into the class itself (like a person having one fixed height they're always sorted by). Comparator defines external, custom sort orders — you can have many, without touching the original class (like sorting the same people by height or age or name, depending on the situation).

class Account implements Comparable<Account> {
    String accountId;
    double balance;

    @Override
    public int compareTo(Account other) {
        return this.accountId.compareTo(other.accountId); // natural order: by ID
    }
}

// External Comparator: sort by balance instead
Comparator<Account> byBalance = (a1, a2) -> Double.compare(a1.balance, a2.balance);

// Or with method references

✓ R4.11 What is try-with-resources in Java? ▸

try-with-resources automatically closes resources (like file streams, DB connections, or Selenium's WebDriver in some patterns) at the end of the block — even if an exception occurs — without needing an explicit finally block. It's like a self-locking door that shuts automatically once you walk out, instead of you having to remember to lock it yourself.

// Traditional way — verbose, error-prone if you forget finally
Connection conn = null;
try {
    conn = DriverManager.getConnection(url, user, pass);
    // use conn
} finally {
    if (conn != null) conn.close();
}

// try-with-resources — automatic cleanup
try (Connection conn = DriverManager.getConnection(url, user, pass);
     Statement stmt = conn.createStatement()) {
    ResultSet rs = stmt.executeQuery("SELECT * FROM accounts");
    // use rs
} // conn and stmt are automatically closed here, even on exception

Requires the resource class to implement AutoCloseable.

                        "Balance mismatch for account " + accountId);
            } else {
                Assert.fail("Account not found: " + accountId);
            }
        }
    }
}

PreparedStatement is preferred over raw Statement — it prevents SQL injection and handles parameter escaping automatically.

✓ R4.14 What is Postman, and how is it different from REST Assured? ▸

Postman is a GUI-based API client — great for manually exploring, debugging, and quickly testing APIs without writing code. REST Assured is a code-based Java library — meant for automating API tests as part of a CI/CD suite, version-controlled alongside the rest of your framework.

Aspect Postman REST Assured
Interface GUI, point-and-click Java code
Best for Manual/exploratory API testing, quick debugging Automated regression suites, CI/CD integration
Version control Collections can be exported as JSON, but less natural in Git diffs Naturally lives in your Java/Maven project, clean Git history
Scripting JavaScript (pre-request/test scripts) Java, integrates with TestNG/JUnit assertions
Automation in CI Via Newman (Postman's CLI runner) Native — runs directly via Maven/Jenkins

In practice, teams often use Postman for exploration during API development, then REST Assured for building the permanent automated regression suite.

✓ R4.15 Equivalence Partitioning and Boundary Value Analysis — with an example ▸

Both are black-box test design techniques used to pick a smart, minimal set of test inputs instead of testing every possible value.

Equivalence Partitioning (EP): Divide inputs into groups ("partitions") that should behave the same way, then test one representative value per group — since testing every value in a group is redundant if they all should behave identically.

Boundary Value Analysis (BVA): Bugs love to hide at the edges of a range, so specifically test values at, just below, and just above each boundary.

Example: A fund transfer field accepts amounts from ₹1 to ₹100,000.

Technique Test values Reasoning
Equivalence Partitioning -50 (invalid, below range), 500 (valid, mid-range), 150000 (invalid, above range) One representative from each partition: invalid-low, valid, invalid-high
Boundary Value Analysis 0, 1, 2 (near lower boundary), 99999, 100000, 100001 (near upper boundary) Bugs commonly occur exactly at "off by one" boundary conditions
✓ R4.16 Agile methodology and QA's role in Scrum ceremonies ▸

Agile is an iterative approach to software delivery — working in short cycles (Sprints, typically 2 weeks) instead of one long waterfall release, allowing faster feedback and adaptation. Scrum is the most common Agile framework, structured around defined ceremonies:

Ceremony QA's role
Sprint Planning Estimate testing effort for stories; flag testability concerns early
Daily Standup Report testing progress, blockers (e.g., "waiting on a test environment fix")
Backlog Refinement Review acceptance criteria for clarity/testability before stories enter a sprint
Sprint Review/Demo Validate that demoed features actually meet acceptance criteria
Retrospective Raise process improvements — e.g., "we need earlier access to test data"

QA in Agile works throughout the sprint (shift-left testing) rather than only at the end — writing test cases as stories are refined, automating as features stabilize, and continuously regression-testing.

✓ R4.17 What is JMeter, and how is it used for performance testing? ▸

Apache JMeter is an open-source tool for load and performance testing — it simulates many virtual users hitting your application simultaneously, to see how it behaves under stress (like flooding a bank's website with thousands of simultaneous "login" requests to see if it slows down or crashes).

Key components: - Thread Group — defines number of virtual users, ramp-up time, loop count. - Sampler (e.g., HTTP Request) — the actual request being sent (e.g., POST /login). - Listener — collects and displays results (response time, throughput, error rate).

Thread Group: 500 users, ramp-up 60s, loop 10 times
  -> HTTP Request Sampler: POST /api/login
  -> Response Assertion: status code == 200
  -> Listener: View Results Tree / Summary Report

Typical metrics QA looks at: average/90th-percentile response time, throughput (requests/sec), and error rate under load — critical for banking systems where transaction endpoints must stay responsive during peak hours.

✓ R4.18 What is Docker, and why would a QA automation engineer use it? ▸

Docker packages an application (and everything it needs — OS libraries, dependencies, config) into a container — a lightweight, portable unit that runs identically anywhere. It's like a shipping container: standardized on the outside so any ship/crane can handle it, regardless of what's packed inside.

Why QA uses it: - Consistent test environments — "works on my machine" problems disappear since the container is identical everywhere (local, CI, staging). - Selenium Grid in containers — spin up isolated browser nodes (selenium/standalone-chrome) instantly without installing browsers locally. - Disposable test databases — spin up a fresh, clean DB container for each test run, then tear it down — no leftover test data polluting future runs.

✓ R4.19 What is a branching strategy? Explain Git Flow / feature branching ▸

A branching strategy is a team's agreed convention for how code changes flow through branches before reaching production — like traffic rules that keep multiple people from stepping on each other's changes.

Feature Branching (most common in modern teams):

main (always production-ready)
  -> develop (integration branch)
        -> feature/fund-transfer-automation
        -> feature/api-regression-suite
        -> bugfix/login-flaky-test
  • Each new feature/fix gets its own branch, created off develop (or main).
  • Work happens in isolation; merged back via a Pull Request with code review.
  • main is always deployable; develop (if used) integrates completed features before release.

Git Flow (a stricter, more structured variant) additionally defines release/* and hotfix/* branches for formal release management — common in regulated environments like banking, where release processes need clear audit trails.

For QA automation repos specifically, this means: your regression suite lives on main/develop, new test additions go through feature branches and PR review just like application code, keeping the framework maintainable and reviewed.

✓ R4.20 Bug vs Defect vs Enhancement — and general best practices for writing good test cases ▸

Terminology (often used loosely, but technically distinct):

Term Meaning
Bug An issue found during testing, before release — the app doesn't behave as expected
Defect An issue found after release (in production) — same root concept as a bug, different discovery phase
Enhancement Not a failure at all — a request to add new capability beyond current requirements

Best practices for writing good test cases: - One test, one purpose — each test case should validate a single, specific behavior, so a failure immediately tells you what broke. - Independent & isolated — a test shouldn't depend on another test's leftover state (e.g., don't assume "account created in Test A" still exists when Test B runs). - Clear pass/fail criteria — the expected result must be unambiguous, not "check if it looks right." - Use realistic + edge-case data — combine typical inputs with boundary/negative values (ties back to EP/BVA above). - Traceable to requirements — each test case should map back to a specific requirement/acceptance criterion, so coverage gaps are visible. - Repeatable & environment-agnostic — should produce the same result on any run/environment, not rely on manual pre-setup steps that aren't automated.

Q 02 Fastest Selenium Locator
Core Selenium

ID is the fastest Selenium locator. When you use By.id(), Selenium internally delegates to the browser's native document.getElementById() — a direct O(1) DOM lookup optimized at the browser engine level. No traversal, no pattern matching, just a direct hash-map lookup.

Speed ranking (fastest → slowest):
ID > Name > CSS Selector > XPath > LinkText > TagName > ClassName
LocatorSpeedWhy
By.id()⚡ FastestNative browser getElementById — O(1) hash lookup
By.name()Very FastBrowser-native getElementsByName
By.cssSelector()FastBrowser CSS engine — highly optimized, faster than XPath
By.xpath()SlowerXML tree traversal — slower, especially with absolute XPath or axes
By.linkText()ModerateScans all anchor tags by text content
By.tagName()ModerateReturns all elements of that tag — potentially large set
By.className()VariableSlower when multiple classes — can match large sets

Why CSS is preferred over XPath in practice: CSS Selectors are natively processed by the browser's rendering engine. XPath requires a separate XPath interpreter, making it generally slower — especially with axes like parent:: or ancestor::, or when traversing deep trees.

💡 Interview TipAdd: "In my GMF project, I always prefer ID or CSS selectors for stable elements. XPath is reserved for cases where the DOM has no stable ID or when I need parent/sibling traversal."

Q 04 What is Selenium?
Fundamentals

Selenium is an open-source browser automation framework used primarily for automating web application testing. It provides a programming interface to write test scripts in multiple languages (Java, Python, C#, JavaScript, Ruby) that control the browser the same way a real user would.

Selenium is not a single tool — it is a suite of tools:

  • Selenium WebDriver — The core API that directly communicates with the browser using the W3C WebDriver protocol. No server needed in Selenium 4.
  • Selenium Grid — Allows running tests in parallel across multiple machines and browsers simultaneously.
  • Selenium IDE — A browser plugin for record-and-playback test creation (limited use in enterprise).
Selenium 4 key changes: Native W3C WebDriver protocol (no JSON Wire Protocol), BiDi (CDP) support for network interception, relative locators, getScreenshotAs() on WebElement, and improved Selenium Grid with Docker support.
💡 Interview TipMention: "Selenium WebDriver talks to the browser via the W3C WebDriver protocol — this is why browser-specific drivers like ChromeDriver are needed as a bridge."
Q 05 Parallel Execution in TestNG
TestNGAdvanced

TestNG supports parallel execution at multiple levels — methods, classes, tests, and suites — configured via the testng.xml suite file. The parallel attribute determines the granularity.

<!-- testng.xml — parallel at method level -->
<suite name="ParallelSuite" parallel="methods" thread-count="4">
  <test name="GMFTests">
    <classes>
      <class name="tests.LoginTest"/>
      <class name="tests.PaymentTest"/>
    </classes>
  </test>
</suite>
parallel= valueWhat runs in parallel
methodsEach @Test method runs in its own thread
classesEach test class runs in its own thread
testsEach <test> XML tag runs in its own thread
instancesEach instance of same class runs in its own thread
Critical: Parallel execution requires ThreadLocal WebDriver. A shared static WebDriver causes race conditions (thread interference). ThreadLocal gives each thread its own isolated driver instance.
public class DriverManager {
    private static ThreadLocal<WebDriver> tlDriver = new ThreadLocal<>();

    public static WebDriver getDriver() { return tlDriver.get(); }

    public static void setDriver(WebDriver driver) { tlDriver.set(driver); }

    public static void quitDriver() {
        tlDriver.get().quit();
        tlDriver.remove(); // Prevent memory leaks
    }
}
💡 Interview Tip"In my GMF project we run parallel at the 'tests' level — 4 threads across Chrome, Firefox, and two environment configs. ThreadLocal WebDriver with @AfterMethod cleanup prevents any cross-contamination."
Q 06 Switching Between Browser Windows
Core Selenium

Each browser window/tab in Selenium has a unique window handle (a string identifier). Use driver.getWindowHandles() to get all open handles and driver.switchTo().window(handle) to switch context.

// Store original window
String mainWindow = driver.getWindowHandle();

// Click action that opens new window
driver.findElement(By.id("openNewWindow")).click();

// Get all window handles (Set — order not guaranteed)
Set<String> allHandles = driver.getWindowHandles();

for (String handle : allHandles) {
    if (!handle.equals(mainWindow)) {
        driver.switchTo().window(handle); // Switch to new window
        break;
    }
}

// Perform actions in new window...
driver.close(); // Close new window
driver.switchTo().window(mainWindow); // Return to main
Selenium 4 upgrade: Use driver.switchTo().newWindow(WindowType.TAB) or WindowType.WINDOW to programmatically open a new tab/window without any JavaScript hack.
// Selenium 4 — open new tab directly
driver.switchTo().newWindow(WindowType.TAB);
driver.get("https://example.com");
Q 07 TestNG Annotation Execution Order
TestNG

TestNG annotations follow a strict hierarchical lifecycle. Annotations at the Suite level run once per suite; Class level once per class; Method level around every single @Test.

Full execution order:

@BeforeSuite → @BeforeTest → @BeforeClass → @BeforeMethod → @Test → @AfterMethod → @AfterClass → @AfterTest → @AfterSuite
AnnotationRunsTypical Use
@BeforeSuiteOnce — before entire suiteGlobal config, DB connection pool
@AfterSuiteOnce — after entire suiteClose connections, generate reports
@BeforeTestOnce per <test> tagBrowser instantiation for a test group
@AfterTestOnce per <test> tagBrowser teardown
@BeforeClassOnce per test classClass-level setup
@AfterClassOnce per test classClass-level cleanup
@BeforeMethodBefore EVERY @Test methodLogin, navigate to URL
@AfterMethodAfter EVERY @Test methodLogout, take screenshot on failure
@TestThe actual test executionVerify business logic
@DataProviderSupplies data to @TestData-driven test parameters

Q 08 Read/Write Excel Using Java
Data-Driven Testing

The standard library for Excel operations in Java automation is Apache POI. It supports both .xls (HSSF) and .xlsx (XSSF) formats. It's the backbone of data-driven testing when test data lives in Excel sheets.

// Maven dependency (pom.xml)
<dependency>
  <groupId>org.apache.poi</groupId>
  <artifactId>poi-ooxml</artifactId> <!-- .xlsx support -->
  <version>5.2.3</version>
</dependency>
// READ from Excel
FileInputStream fis = new FileInputStream("testdata/GMFData.xlsx");
Workbook wb = new XSSFWorkbook(fis);
Sheet sheet = wb.getSheet("LoginData");

for (Row row : sheet) {
    String username = row.getCell(0).getStringCellValue();
    String password = row.getCell(1).getStringCellValue();
    System.out.println(username + " | " + password);
}
wb.close(); fis.close();

// WRITE to Excel
Workbook newWb = new XSSFWorkbook();
Sheet s = newWb.createSheet("Results");
Row r = s.createRow(0);
r.createCell(0).setCellValue("Test Case");
r.createCell(1).setCellValue("Status");

FileOutputStream fos = new FileOutputStream("output/Results.xlsx");
newWb.write(fos);
newWb.close(); fos.close();
In modern BDD/TestNG setups, Excel data is fed via @DataProvider — the provider reads the sheet and returns Object[][] which TestNG maps to @Test method parameters.
Q 09 Types of XPath
XPath

There are two fundamental types of XPath expressions in Selenium:

1. Absolute XPath — Starts from root (/html). Brittle — any structural DOM change breaks it.

Example: /html/body/div[1]/form/input[2]
2. Relative XPath — Starts with //, searches anywhere in the DOM. Robust and preferred.

Example: //input[@id='username']

Within Relative XPath, you have several expression techniques:

TechniqueExampleUse Case
Attribute-based//input[@name='email']Stable attribute match
Text-based//button[text()='Submit']Match by visible text
contains()//a[contains(@href,'login')]Partial attribute match
starts-with()//input[starts-with(@id,'user')]Dynamic ID prefix
AND / OR//input[@type='text' and @name='email']Multiple conditions
Axes//label[text()='Name']/following-sibling::inputDOM traversal
Index(//input[@type='text'])[2]nth element in set
Q 10 Selenium 4 WebElement Screenshot API
Selenium 4New Feature

Selenium 4 introduced the ability to capture screenshots of individual WebElements — not just the entire browser viewport. This is a major improvement for debugging and visual regression testing of specific components.

// Full-page screenshot (Selenium 3 & 4)
TakesScreenshot ts = (TakesScreenshot) driver;
File fullPage = ts.getScreenshotAs(OutputType.FILE);
FileUtils.copyFile(fullPage, new File("screenshots/fullPage.png"));

// ✅ Selenium 4 — WebElement-level screenshot (NEW)
WebElement card = driver.findElement(By.id("loanSummaryCard"));
File elementShot = card.getScreenshotAs(OutputType.FILE);
FileUtils.copyFile(elementShot, new File("screenshots/loanCard.png"));

// As Base64 string (useful for Extent Reports embedding)
String base64 = card.getScreenshotAs(OutputType.BASE64);
Real-world use: In GMF testing, I capture element-level screenshots of the DDC confirmation email preview component and embed them as Base64 in Extent Reports — no full-page noise, just the relevant component.

Other major Selenium 4 additions: Relative Locators (RelativeBy.near(), .above(), .below()), CDP (Chrome DevTools Protocol) for network throttling/request interception, and BiDirectional communication.

Q 12 Select Class for Dropdowns
Core Selenium

The Select class in Selenium (from org.openqa.selenium.support.ui.Select) provides a clean API for interacting with native HTML <select> dropdowns. It supports selection by visible text, value attribute, or index.

WebElement dropdownEl = driver.findElement(By.id("dueDateDropdown"));
Select dropdown = new Select(dropdownEl);

// 3 ways to select
dropdown.selectByVisibleText("15th of Month");   // by text shown to user
dropdown.selectByValue("15");                    // by <option value="15">
dropdown.selectByIndex(2);                       // 0-based index

// Get selected option
String selected = dropdown.getFirstSelectedOption().getText();

// Get all options
List<WebElement> allOptions = dropdown.getOptions();

// Multi-select dropdown
if (dropdown.isMultiple()) {
    dropdown.selectByVisibleText("Option A");
    dropdown.selectByVisibleText("Option B");
    dropdown.deselectByVisibleText("Option A");
    dropdown.deselectAll();
}
Important: The Select class ONLY works on native <select> HTML elements. Custom dropdowns (built with <div>, <ul>, or React/Angular components) require clicking to open and then clicking the option — NOT the Select class.

Q 15 Waits — Implicit, Explicit & Fluent
AdvancedSynchronization
Wait TypeScopeConditionPolling
Implicit WaitGlobal — all findElement callsElement present in DOMFixed — framework default
Explicit WaitSpecific element + conditionAny ExpectedConditionDefault 500ms
Fluent WaitSpecific element + conditionAny ExpectedCondition + ignore specific exceptionsConfigurable interval
// 1. IMPLICIT WAIT — applies globally, set once
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));

// 2. EXPLICIT WAIT — precise condition-based wait
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(15));
WebElement element = wait.until(
    ExpectedConditions.elementToBeClickable(By.id("submitBtn"))
);

// 3. FLUENT WAIT — configurable polling + exception tolerance
Wait<WebDriver> fluentWait = new FluentWait<>(driver)
    .withTimeout(Duration.ofSeconds(30))
    .pollingEvery(Duration.ofMillis(500))
    .ignoring(NoSuchElementException.class)
    .ignoring(StaleElementReferenceException.class);

WebElement el = fluentWait.until(d -> d.findElement(By.id("dynamicEl")));

// Common ExpectedConditions
ExpectedConditions.visibilityOfElementLocated(by);
ExpectedConditions.elementToBeClickable(by);
ExpectedConditions.textToBePresentInElement(el, "text");
ExpectedConditions.alertIsPresent();
ExpectedConditions.invisibilityOf(el);
Anti-pattern: Never mix Implicit + Explicit waits. They conflict — implicit wait time adds to explicit wait polling, causing unpredictable timeouts. Use explicit wait exclusively in production frameworks.

Q 16 TimeoutException & Synchronization
Exception Handling

TimeoutException is thrown when a WebDriverWait or FluentWait condition is not met within the specified timeout period. It's the most common wait-related exception in automation — and it's a synchronization failure, not a test failure per se.

Root causes: Element takes longer than expected to appear/become clickable; wrong wait condition used; element is in DOM but not visible; network latency; async JavaScript not completed.

Synchronization is the practice of aligning your test script timing with the application's actual response time. The application's DOM state changes asynchronously (AJAX, JavaScript rendering, API calls) — your test must wait intelligently rather than use fixed Thread.sleep().

ApproachQualityNotes
Thread.sleep(3000)❌ Anti-patternWastes time, unreliable, hard to maintain

Explicit Wait✅ GoodCondition-specific, precise

Custom ExpectedCondition✅✅ BestBusiness-logic specific conditions

        .executeScript("return document.readyState")
        .equals("complete");

Q 22 Page Object Model (POM)
Design PatternFramework

Page Object Model (POM) is a design pattern in Selenium that creates a class for each web page (or component), encapsulating its elements and actions. This separates the test logic from the page interaction code, making the framework maintainable, readable, and reusable.

Core principle: If a page's UI changes, only the Page Object class needs updating — not every test that uses that page. DRY (Don't Repeat Yourself) applied to test automation.
// Page Object class — encapsulates elements and actions
public class GMFLoginPage {
    private WebDriver driver;

    // Page Factory — lazy initialization of elements
    @FindBy(id = "username")
    private WebElement usernameField;

    @FindBy(id = "password")
    private WebElement passwordField;

    @FindBy(css = "button[type='submit']")
    private WebElement loginButton;

    @FindBy(css = ".error-message")
    private WebElement errorMessage;

    public GMFLoginPage(WebDriver driver) {
        this.driver = driver;
        PageFactory.initElements(driver, this); // Init @FindBy fields
    }

    public GMFDashboardPage login(String user, String pass) {
        usernameField.clear();
        usernameField.sendKeys(user);
        passwordField.sendKeys(pass);
        loginButton.click();
        return new GMFDashboardPage(driver); // Fluent chaining
    }

    public String getErrorMessage() { return errorMessage.getText(); }
}

// Test class — clean, readable, no locators visible
public class LoginTest {
    @Test
    public void validLoginTest() {
        GMFLoginPage loginPage = new GMFLoginPage(driver);
        GMFDashboardPage dashboard = loginPage.login("user@gmf.com", "pass");
        Assert.assertTrue(dashboard.isLoaded());
    }
}
POM BenefitHow It Helps
MaintainabilityLocator change in one place — not 50 test methods
ReadabilityTests read like business flows, not Selenium API calls
ReusabilityLogin page object reused across all tests needing login
Separation of concernsTest logic ≠ UI interaction code
💡 Interview Tip"I use Page Factory with @FindBy annotations in my GMF framework — it initializes elements lazily via proxies, reducing stale element issues. I also apply the fluent page object pattern where each action returns the next page object, enabling readable test chaining."
Q 23 Maven for Dependency Management

Maven Lifecycle phases relevant to QA: validate → compile → test → package → verify → install → deploy. The test phase runs via maven-surefire-plugin which picks up your testng.xml.

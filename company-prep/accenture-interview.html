2. Describe the automation framework used in your project

Hybrid Framework — most common, safest answer to give:

  • Design pattern: Page Object Model (POM) + Page Factory
  • Test orchestration: TestNG (annotations, data providers, parallel execution, suite XML)
  • Build tool: Maven (dependency management, surefire plugin)
  • Data-driven layer: Excel/JSON/Properties via Apache POI or Jackson
  • Reporting: ExtentReports / Allure
  • Logging: Log4j2
  • CI/CD: Jenkins triggers Maven build → runs testng.xml → publishes reports
  • Version control: Git/GitHub, feature-branch workflow
public class LoginPage extends BasePage {
    @FindBy(id = "username")
    private WebElement usernameField;

    @FindBy(id = "password")
    private WebElement passwordField;

    @FindBy(id = "loginBtn")
    private WebElement loginButton;

    public LoginPage(WebDriver driver) {
        super(driver);
        PageFactory.initElements(driver, this);
    }

    public HomePage login(String user, String pass) {
        usernameField.sendKeys(user);
        passwordField.sendKeys(pass);
        loginButton.click();
        return new HomePage(driver);
    }
}
3. How would you add new fields to the object repository?

A. Page Factory style (annotation-based):

@FindBy(id = "newField")
private WebElement newField;

Add the locator to the relevant Page class, then expose an action method for it.

B. Properties-file / Excel-based Object Repository:

  1. Add a new entry: newField=id,newFieldId
  2. Loaded via Properties.load() or Apache POI
  3. Retrieved dynamically: driver.findElement(By.id(orProperties.getProperty("newField")))

Process to mention:

  1. Identify the correct page class / repository file for the module.
  2. Inspect the DOM to pick the most stable locator (id > name > CSS > XPath).
  3. Add the locator with a consistent naming convention.
  4. Add a corresponding action/utility method — tests should never call findElement directly.
  5. Run a quick smoke check before committing.

5. Difference between single slash (/) and double slash (//) in XPath
/ (single)// (double)
TypeAbsolute pathRelative path
SearchStarts from document root, exact hierarchySearches anywhere in the DOM, any level
Example/html/body/div/form/input//input[@id='username']
FragilityBreaks easily if DOM structure changesMore resilient to structural changes
In real frameworks, // with attribute conditions is used almost exclusively — absolute paths are too brittle against UI changes.
6. Different TestNG annotations and their execution order

Common annotations: @BeforeSuite, @BeforeTest, @BeforeClass, @BeforeMethod, @Test, @AfterMethod, @AfterClass, @AfterTest, @AfterSuite

@BeforeSuite
  @BeforeTest
    @BeforeClass
      @BeforeMethod
        @Test
      @AfterMethod
    @AfterClass
  @AfterTest
@AfterSuite
  • @BeforeMethod/@AfterMethod — run before/after every @Test method.
  • @BeforeClass/@AfterClass — run once per class.
  • @BeforeTest/@AfterTest — run once per <test> tag in testng.xml.
  • @BeforeSuite/@AfterSuite — run once for the entire suite.

Other important annotations: @DataProvider, @Test(priority=1), @Test(dependsOnMethods={"login"}), @Test(enabled=false), @Test(invocationCount=3), @Test(retryAnalyzer=...)

8. Explain Jenkins and its role in automation testing

Jenkins is an open-source CI/CD automation server. In automation testing, it:

  1. Triggers test runs automatically — on commit (webhook), schedule (cron), or manually.
  2. Builds the project via Maven (mvn clean test -Dsuite=regression.xml).
  3. Executes the TestNG suite and collects results.
  4. Publishes reports (Extent, Allure, JUnit XML plugin) as build artifacts.
  5. Sends notifications — email/Slack on failure, pass/fail badges.
  6. Enables pipeline-as-code via a Jenkinsfile.
pipeline {
    agent any
    stages {
        stage('Checkout') { steps { git 'https://github.com/repo.git' } }
        stage('Build & Test') { steps { sh 'mvn clean test -DsuiteXmlFile=testng.xml' } }
        stage('Report') { steps { publishHTML(target: [reportDir: 'test-output', reportFiles: 'index.html', reportName: 'Extent Report']) } }
    }
    post { always { junit 'test-output/*.xml' } }
}
9. How do you handle alerts in Selenium? 
Alert alert = driver.switchTo().alert();

alert.accept();              // clicks OK
alert.dismiss();             // clicks Cancel
String text = alert.getText();      // reads alert message
alert.sendKeys("input text");       // for prompt-type alerts
  • Simple alert → accept()
  • Confirmation alert → accept() / dismiss()
  • Prompt alert → sendKeys() then accept()
new WebDriverWait(driver, Duration.ofSeconds(10))
    .until(ExpectedConditions.alertIsPresent());
Selenium only handles JavaScript/browser-native alerts, not OS-level pop-ups — those need the Robot class or AutoIT.

11. What is polymorphism, and how is it applied in Selenium?

Polymorphism = the same interface/method behaves differently depending on the object or arguments.

Runtime polymorphism in Selenium:

WebDriver driver = new ChromeDriver();   // or FirefoxDriver(), EdgeDriver()
driver.get("https://example.com");

WebDriver is an interface; ChromeDriver, FirefoxDriver, EdgeDriver are concrete implementations. You code against the interface, and the actual browser behavior is decided at runtime based on the object instantiated — which is why switching browsers is a one-line change.

Compile-time polymorphism (method overloading) — see Q12 below.

12. What is method overloading, and when do you use it in Selenium?

Overloading = same method name, different parameter list, resolved at compile time.

public class WaitUtils {

    // Wait using a By locator
    public WebElement waitForElement(WebDriver driver, By locator) {
        return new WebDriverWait(driver, Duration.ofSeconds(10))
                .until(ExpectedConditions.visibilityOfElementLocated(locator));
    }

    // Wait using a By locator with custom timeout
    public WebElement waitForElement(WebDriver driver, By locator, int timeoutInSeconds) {
        return new WebDriverWait(driver, Duration.ofSeconds(timeoutInSeconds))
                .until(ExpectedConditions.visibilityOfElementLocated(locator));
    }

    // Wait on an already-located WebElement
    public WebElement waitForElement(WebDriver driver, WebElement element) {
        return new WebDriverWait(driver, Duration.ofSeconds(10))
                .until(ExpectedConditions.visibilityOf(element));
    }
}

This gives test writers a single, flexible, discoverable API (waitForElement(...)) instead of forcing multiple differently-named methods.

3. What is POM, and why is the object repository used?

Page Object Model — each web page/screen is a class containing locators (fields) and actions (methods that use those locators).

Why an Object Repository matters:

  1. Maintainability — a locator change is fixed in one place, not across every test file.
  2. Reusability — page methods are reused across many test cases.
  3. Readability — tests read as business language (loginPage.login(user, pass)) instead of raw Selenium calls.
  4. Separation of concerns — test logic stays separate from UI interaction logic.
4. Purpose of the Robot class in Selenium

java.awt.Robot is a core Java class used to simulate OS-level keyboard and mouse events, outside the browser DOM.

Common use cases:

  • Native file upload dialogs Selenium can't directly access.
  • Windows authentication pop-ups (basic auth dialogs).
  • Keyboard shortcuts (Ctrl+C, Ctrl+V, Alt+Tab).
  • Capturing screen pixels (createScreenCapture).
Robot robot = new Robot();
robot.keyPress(KeyEvent.VK_ENTER);
robot.keyRelease(KeyEvent.VK_ENTER);
5. Why is Page Factory used in object repositories?

PageFactory is Selenium's built-in mechanism to initialize @FindBy-annotated WebElement fields.

  1. Cleaner, declarative locators — @FindBy(id="username") instead of repeated findElement calls.
  2. Lazy initialization — elements aren't located until used, via a dynamic proxy.
  3. Centralized initialization — one call, PageFactory.initElements(driver, this), wires up the entire page class.
  4. Supports @FindBys/@FindAll — for chained or OR-based locator strategies.
public class LoginPage {
    @FindBy(id = "username") WebElement username;
    @FindBy(id = "password") WebElement password;

    public LoginPage(WebDriver driver) {
        PageFactory.initElements(driver, this);
    }
}
6. How do you launch Internet Explorer in Selenium WebDriver? 
System.setProperty("webdriver.ie.driver", "C:\\drivers\\IEDriverServer.exe");

InternetExplorerOptions options = new InternetExplorerOptions();
options.ignoreZoomSettings();
options.introduceFlakinessByIgnoringSecurityDomains();
options.requireWindowFocus();

WebDriver driver = new InternetExplorerDriver(options);
driver.get("https://example.com");

Key gotchas:

  • IE requires Protected Mode set identically across all security zones (Internet, Local Intranet, Trusted Sites, Restricted Sites) — mismatches cause NoSuchWindowException.
  • Zoom level must be 100%.
  • IE driver is slower and flakier than Chrome/Firefox — typically only used for legacy banking apps still mandating IE11.

8. How do you work with frames? How many ways to pass values?

Frames create a separate DOM context — you must switch into a frame before interacting with elements inside it.

Three ways to switch into a frame:

driver.switchTo().frame(0);                      // 1. By index
driver.switchTo().frame("frameNameOrId");         // 2. By name or ID
WebElement frameElement = driver.findElement(By.xpath("//iframe[@class='payment']"));
driver.switchTo().frame(frameElement);             // 3. By WebElement

Coming back out:

driver.switchTo().defaultContent();   // back to the main page
driver.switchTo().parentFrame();      // one level up (for nested frames)
9. Explain the use of XPath and sibling elements

Sibling axes are used when an element doesn't have a unique/stable locator itself but sits next to one that does.

// Find the input right after a label with text "Email"
//label[text()='Email']/following-sibling::input[1]

// Find element before a given sibling
//div[@class='footer']/preceding-sibling::div[1]

// All following siblings (not just the immediate one)
//h2[text()='Section']/following-sibling::p

Common XPath functions worth mentioning: contains(), starts-with(), text(), normalize-space(), and logical and/or.

10. Implicit wait vs explicit wait — difference and syntax
Implicit WaitExplicit Wait
ScopeApplies globally to every findElement call for the driver's lifetimeApplies to a specific element/condition only
BehaviorPolls the DOM for a fixed max time before throwing NoSuchElementExceptionPolls until a specific ExpectedCondition is met
FlexibilityOne-size-fits-all timeoutDifferent waits/conditions per element
Best practiceSet once, low value (5–10s)Preferred for flaky/dynamic elements

Implicit wait syntax:

driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));

Explicit wait syntax:

WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(15));
WebElement element = wait.until(ExpectedConditions.elementToBeClickable(By.id("submitBtn")));
Gotcha: never mix implicit and explicit waits in the same script — it can cause unpredictable wait times since the two timers can stack unexpectedly.
11. Program for taking a screenshot in Selenium 
import org.apache.commons.io.FileUtils;
import org.openqa.selenium.*;
import java.io.File;
import java.io.IOException;

public class ScreenshotUtil {

    public static String captureScreenshot(WebDriver driver, String screenshotName) {
        TakesScreenshot ts = (TakesScreenshot) driver;
        File source = ts.getScreenshotAs(OutputType.FILE);
        String destPath = System.getProperty("user.dir")
                + "/screenshots/" + screenshotName + "_" + System.currentTimeMillis() + ".png";
        File destination = new File(destPath);
        try {
            FileUtils.copyFile(source, destination);
        } catch (IOException e) {
            e.printStackTrace();
        }
        return destPath;
    }
}

Usage in a TestNG listener (auto-capture on failure):

@Override
public void onTestFailure(ITestResult result) {
    WebDriver driver = DriverManager.getDriver();
    ScreenshotUtil.captureScreenshot(driver, result.getName());
}

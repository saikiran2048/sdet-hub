01Difference between ArrayList and LinkedList in Javaround 1▶
AspectArrayListLinkedList
StructureDynamic arrayDoubly linked list
get(index)O(1)O(n)
Insert/delete middleO(n) — shifts elementsO(1) once node is found, O(n) to find it
Insert/delete endsAmortized O(1) at end, O(n) at startO(1) both ends
Best forFrequent readsFrequent insert/delete, Queue/Deque use
List<String> arrayList = new ArrayList<>();
arrayList.add("A"); arrayList.add("B");
System.out.println(arrayList.get(0)); // O(1)

LinkedList<String> linkedList = new LinkedList<>();
linkedList.addFirst("X");
linkedList.addLast("Y"); // O(1), unlike ArrayList.add(0,...)
How to answer: Lead with the underlying data structure difference — everything else follows logically from that.
02Purpose of the synchronized block in Javaround 1▶

synchronized ensures only one thread can execute a block/method on a given monitor at a time, preventing race conditions on shared mutable data.

public class Counter {
    private int count = 0;
    private final Object lock = new Object();
    public void increment() {
        synchronized (lock) { count++; } // only this critical section is locked
    }
}

In automation: relevant when writing parallel test execution frameworks — ThreadLocal WebDriver instances, shared report/logging objects, shared counters for test data generation.

How to answer: Explain why (thread safety) before how (method vs block), then tie it to a real scenario like parallel TestNG execution.

06Difference between @BeforeClass and @BeforeTest (TestNG)round 1▶

@BeforeClass runs once before the first @Test in that class. @BeforeTest runs once before all test methods in classes under a <test> tag in testng.xml — can span multiple classes.

Hierarchy: @BeforeSuite → @BeforeTest → @BeforeClass → @BeforeMethod → @Test

How to answer: Draw the hierarchy verbally — it instantly disambiguates XML `` scope from Java class scope.

13The * and ^ symbols in CSS selectorsround 2▶

* (universal selector) selects all elements. [attr^=value] selects elements whose attribute starts with a given string.

How to answer: Give both symbols with one small example each, no padding — brevity itself shows confidence with CSS selectors.

18What is method hiding in Java?round 2▶

Occurs when a static method in a subclass has the same signature as one in the parent. Static methods resolve by reference type at compile time, not object type at runtime — so the subclass "hides" rather than overrides.

class Parent { static void display(){ System.out.println("Parent"); } }
class Child extends Parent { static void display(){ System.out.println("Child"); } }

Parent p = new Child();
p.display(); // prints "Parent" — resolved by reference type
How to answer: Say explicitly: "static methods resolve by reference type at compile time, instance methods by object type at runtime."

19Page Object Model vs Page Factory vs Hybrid framework — which do you use and why?architecture▶
PatternWhat it isTrade-off
POMEach page is a class; elements located inside methodsExplicit, but re-locates elements every call
Page FactoryPOM + @FindBy, lazy init via PageFactory.initElements()Cleaner syntax, but can mask stale-element issues on dynamic pages
HybridPOM/Factory + data-driven + keyword layerMore setup, scales for mixed technical/non-technical contributors
public class LoginPage {
    @FindBy(id = "username") WebElement usernameField;
    @FindBy(id = "loginBtn") WebElement loginButton;

    public LoginPage(WebDriver driver) {
        PageFactory.initElements(driver, this);
    }
    public void login(String user) { usernameField.sendKeys(user); loginButton.click(); }
}

Default choice: POM with explicit waits for most work — Page Factory's lazy binding causes subtle stale-element bugs on SPA-heavy pages. Full hybrid only when non-automation stakeholders author test cases.

How to answer: State which one you actually chose and name the one real bug that shaped that decision.
20How would you scale an automation framework across multiple teams?architecture▶
  • Core framework as a shared library — versioned internal Maven/Gradle artifact, not copy-pasted per repo.
  • Layered ownership — core team owns the engine, feature teams own page objects/step definitions/data.
  • Config-driven environments — externalized YAML/properties so the same suite runs across teams' pipelines.
  • Consistent standards — shared naming conventions, reporting format, CI pipeline template.
  • Versioning & backward compatibility — treat the framework as a product with a deprecation cycle.
How to answer: Frame the core framework as an internal "product" with versioning and consumers.

22How do you handle flaky tests at scale (hundreds of tests, not just one)?architecture▶
  • Quarantine, don't ignore — tag flaky tests, route to a separate CI job, keep tracking them.
  • Root-cause categorize — timing/sync, test interdependency, environment instability, real race conditions.
  • Standardize waits — replace scattered Thread.sleep() with one explicit-wait utility.
  • Bounded retry with visibility — TestNG IRetryAnalyzer, log every retry so counts stay visible.
  • Track flakiness as a metric — dashboard over time, owned like tech debt.
How to answer: Lead with "quarantine + root-cause categorize" — shows you don't just slap a retry annotation on everything.
Added — Concurrency
23How do you manage WebDriver instances safely during parallel test execution?concurrency▶
public class DriverManager {
    private static ThreadLocal<WebDriver> driver = new ThreadLocal<>();
    public static WebDriver getDriver() {
        if (driver.get() == null) driver.set(new ChromeDriver());
        return driver.get();
    }
    public static void quitDriver() {
        if (driver.get() != null) { driver.get().quit(); driver.remove(); }
    }
}

Paired with TestNG's parallel="methods"/"classes" and thread-count in suite XML.

How to answer: Explicitly mention driver.remove() — forgetting it is the #1 real bug (thread-pool reuse leaks stale references).
24Explain ExecutorService / CompletableFuture and where you'd use them in a test frameworkconcurrency▶
ExecutorService executor = Executors.newFixedThreadPool(5);
List<Future<Boolean>> results = new ArrayList<>();
for (String endpoint : endpoints) {
    results.add(executor.submit(() -> validateApiResponse(endpoint)));
}
for (Future<Boolean> r : results) assertTrue(r.get());
executor.shutdown();

// CompletableFuture — async, non-blocking chaining
CompletableFuture<String> apiCall = CompletableFuture.supplyAsync(() -> callApi("/orders"));
CompletableFuture<String> dbCall  = CompletableFuture.supplyAsync(() -> queryDb("orders"));
CompletableFuture.allOf(apiCall, dbCall).join();
assertEquals(apiCall.get(), dbCall.get());

Real use case: reconciliation testing — fetching API, DB, and Kafka event concurrently instead of sequentially cuts execution time.

How to answer: If you've built a reconciliation-style framework, this is your strongest story.
25Beyond the basic definition — what thread-safety issues have you actually hit in parallel test runs?concurrency▶
  • Shared static state — a static counter/report object mutated by multiple threads without sync.
  • Non-thread-safe collections — plain HashMap/ArrayList shared across threads → use ConcurrentHashMap/CopyOnWriteArrayList.
  • Shared test data records — two parallel tests mutating the same seeded DB row → false failures.
  • Extent Reports thread context — ExtentTest must be stored in a ThreadLocal too, or parallel logs interleave into the wrong test's report node.
How to answer: The Extent Reports + ThreadLocal detail is a strong specific — most candidates only think about the driver.

27How do you prioritize what to test when you don't have time to test everything?strategy▶

Prioritize by (impact of failure) × (likelihood of failure), not ease of testing.

  • High impact + high change frequency → top priority
  • High impact + stable → spot-check via existing regression
  • Low impact + high change → light coverage
  • Low impact + stable → deprioritize under time pressure

In BFSI: compliance-sensitive and money-movement flows sit at the top regardless of how small the change looks.

How to answer: Ground the impact-×-likelihood framing in a real domain example (BFSI payment/compliance flow).

Added — API & Services
29What is API contract testing and how is it different from regular API testing?api & services▶

Regular API testing validates behavior. Contract testing validates that the structure/schema between consumer and provider stays compatible — critical for independently-deployed microservices.

  • Consumer-driven contracts (Pact) — consumer defines expected contract; provider's build verifies it before deploying.
  • Schema validation — simpler: validate response against a JSON Schema/OpenAPI spec.
given()
    .when().get("/api/orders/101")
    .then().assertThat()
    .body(matchesJsonSchemaInClasspath("order-schema.json"));
How to answer: "Behavior testing checks values, contract testing checks structure/compatibility across teams."
30When and how do you use service virtualization / mocking (e.g., WireMock)?api & services▶

Used when a dependent service is unavailable, unstable, or expensive to call in lower environments — e.g., a third-party credit bureau API in BFSI.

WireMockServer wireMockServer = new WireMockServer(8089);
wireMockServer.start();
wireMockServer.stubFor(get(urlEqualTo("/credit-score/101"))
    .willReturn(aResponse().withStatus(200)
        .withBody("{ \"score\": 780, \"status\": \"APPROVED\" }")));
  • Positive scenario mocking — reliable, fast happy-path.
  • Negative/edge mocking — simulate timeouts/5xx that are hard to trigger against a real service.
How to answer: Mention using mocks specifically for negative/error scenarios — that's what separates knowing the tool from using it well.

Core Java & Selenium

01 findElement() vs findElements() — what's the difference?

findElement() returns a single WebElement and throws NoSuchElementException if nothing matches. findElements() returns a List<WebElement> and returns an empty list instead of throwing — safer for presence checks.

// findElement — throws if not found
WebElement btn = driver.findElement(By.id("submitBtn"));

// findElements — safe presence check, never throws
List<WebElement> rows = driver.findElements(By.cssSelector("table tbody tr"));
boolean isPresent = !driver.findElements(By.id("errorBanner")).isEmpty();
Mention: findElements() is your go-to for conditional checks — avoids try/catch overhead from NoSuchElementException.
02 How do you handle dynamic web elements in Selenium?

Use relative locators with contains() / starts-with(), anchor to a stable parent element, or build the locator with a runtime variable.

// Relative XPath — avoid absolute paths
driver.findElement(By.xpath("//button[contains(text(),'Submit')]"));
driver.findElement(By.xpath("//input[starts-with(@id,'txn_')]"));

// CSS partial attribute match
driver.findElement(By.cssSelector("input[id^='txn_']"));

// Runtime-built locator
public WebElement getTransactionRow(String txnId) {
    return driver.findElement(
        By.xpath("//td[text()='" + txnId + "']/ancestor::tr")
    );
}
GMF context: confirmation reference numbers in DDC emails were dynamic — anchored locator using contains(@data-ref,'DDC') on the email preview panel stayed stable across environments.

05 How do you handle multiple windows/tabs in Selenium? 
String parentWindow = driver.getWindowHandle();

// Reusable utility — wait for new window, then switch
public void switchToNewWindow(String parentHandle) {
    new WebDriverWait(driver, Duration.ofSeconds(10))
        .until(d -> d.getWindowHandles().size() > 1);
    driver.getWindowHandles().stream()
        .filter(h -> !h.equals(parentHandle))
        .findFirst()
        .ifPresent(h -> driver.switchTo().window(h));
}

// ... actions on new window ...
driver.close();
driver.switchTo().window(parentWindow);
06 How do you design a Page Object Model (POM) framework?

Separate page structure (locators + actions) from test logic. One page class per page, common utilities in a BasePage.

// BasePage.java
public class BasePage {
    protected WebDriver driver;
    protected WebDriverWait wait;

    BasePage(WebDriver driver) {
        this.driver = driver;
        this.wait = new WebDriverWait(driver, Duration.ofSeconds(15));
        PageFactory.initElements(driver, this);
    }
}

// PaymentPage.java — fluent return for chaining
public class PaymentPage extends BasePage {
    @FindBy(id = "paymentAmount") private WebElement amountField;
    @FindBy(css = "button[data-action='submit-payment']") private WebElement submitBtn;

    public ConfirmationPage submitPayment() {
        wait.until(ExpectedConditions.elementToBeClickable(submitBtn)).click();
        return new ConfirmationPage(driver);
    }
}
Mention the folder structure: pages/ · utils/ (DriverFactory, ConfigReader) · test/base · resources/config + testdata.

09 How do you handle exceptions in Selenium scripts? 
// StaleElementReferenceException — retry pattern
public WebElement getStaleProofElement(By locator) {
    int retries = 3;
    while (retries-- > 0) {
        try { return driver.findElement(locator); }
        catch (StaleElementReferenceException e) { /* retry */ }
    }
    throw new RuntimeException("Element still stale: " + locator);
}

// ElementClickInterceptedException — JS click fallback
public void safeClick(WebElement element) {
    try { element.click(); }
    catch (ElementClickInterceptedException e) {
        ((JavascriptExecutor) driver).executeScript("arguments[0].click();", element);
    }
}

11 ⭐ extra — How would you automate OTP-based login flows?

This comes up often in BFSI interviews because OTP breaks pure UI automation. Three real approaches, in order of preference:

  1. Test environment bypass: request a static/whitelisted OTP for QA environments (e.g. 123456 always valid in UAT) — agreed with dev team. Most common in practice.
  2. API-level OTP retrieval: if OTP is emailed/SMS'd, pull it via a test mailbox API (Mailosaur, Gmail API) or an internal SMS gateway test endpoint.
  3. DB lookup: if OTP is stored temporarily in a DB/cache (Redis), query it directly post-trigger using JDBC/Jedis client in the test.
// Pattern: trigger OTP, then fetch via Redis before it expires
String otp = redisClient.get("otp:" + mobileNumber);
loginPage.enterOtp(otp);
Mention: never hardcode production OTP bypass logic — always environment-gated, never compiled into the prod build path.

03 Best practices to make automation scripts more maintainable?
  • Single responsibility — one page class per page
  • No hardcoded waits, ever
  • Externalize all test data
  • Descriptive method names (clickSubmitPaymentButton() not clickButton2())
  • Retry only for flaky infra, never to mask real failures
  • Centralized ThreadLocal driver management
  • Assertions always carry a failure message with context
  • Log every meaningful step

06 How do you decide which test cases to automate?

Automate: high-frequency regression/smoke, stable business rules, data-driven combinations, cross-browser checks, API contract validation.

Don't automate: exploratory/usability testing, one-time tests, CAPTCHA/biometric/OTP flows without a bypass, pixel-level visual diffs (use Applitools/Percy instead).

Framework: ROI = frequency × effort to automate × risk of failure. High-frequency + low-effort + high-risk goes first.

GMF DDC email validation: an automated API contract test flagged that the dueDate field in DDC confirmation emails returned the old due date when the change happened within 24 hours of billing cycle close. 06 ⭐ extra — How do you handle disagreement with a manager about release readiness / sign-off?

This tests whether you can hold a quality line under pressure without becoming combative — a direct read on seniority.

Approach: separate facts from opinion. Bring data, not a gut feeling — defect severity, open P1/P2 count, automation pass rate, risk areas with zero coverage. Frame it as a risk decision for the business to make, not a QA veto.

Example framing: "Here's the current state — 2 open P2 defects in the payment confirmation flow, regression pass rate at 94%, and the DDC email module has no automated coverage yet. I'm not blocking the release, but I want the risk documented and a rollback plan in place if we proceed."

Key point to make out loud: "I make the risk visible and let the business own the decision — quality isn't about saying no, it's about making sure no one signs off blind."
